# Terminal emulator (`sverb-term`)

SPEC §7.1, §14.2, §17, §22.4. Implemented in M1-09; rendering is M1-10.

## Layout

| Module | Contents |
|---|---|
| `emulator.rs` | `Emulator` trait and the emulator-agnostic types (`GridPoint`, `Match`, `CursorInfo`, `TermEvent`, `ColorScheme`, `ViewState`). `ColorScheme`/`ViewState` are provisional: M1-10 moves/extends them. |
| `modes.rs` | `TermModes` (DECCKM, DECKPAM, mouse mode + encoding, 2004, 1004, alt screen, LNM, modifyOtherKeys, kitty flags, cursor). |
| `policy.rs` | Security limits (title ≤ 256 chars, cwd length, OSC 52 payload cap) and `ClipboardWritePolicy` (`never`/`ask`/`always`), which the UI applies (M1-11). |
| `charset.rs` | `CharsetCodec`: streaming `encoding_rs` decode (remote → UTF-8, before `feed`) and encode (input → host charset). |
| `alacritty/` | `AlacrittyEmulator` (`mod.rs`), the synchronous event `Listener`, the side scanner for sequences alacritty ignores, and `snapshot_vt`. |

## How `AlacrittyEmulator` works

- `feed` runs `vte::ansi::Processor::advance(&mut term, bytes)`. The listener queues alacritty
  events in a `Vec` (no channels), drained after each `feed`:
  - `PtyWrite` → `take_responses()` (DA1/DA2, DSR/CPR, DECRQM, `CSI 18 t`, kitty `CSI ? u`).
    These must be written back to the channel or vim/fish hang.
  - `ColorRequest` → answered from the remote's own OSC 4/10/11/12 overrides, else the pane
    `ColorScheme` (default: xterm palette, light on black).
  - `TextAreaSizeRequest` → cells × `set_pixel_size` (0 when unknown).
  - `Title`/`ResetTitle` → `TermEvent::Title` (sanitized), `Bell`, `ClipboardStore` →
    `TermEvent::ClipboardWriteRequest`.
  - `ClipboardLoad` (OSC 52 read) is **dropped inside the listener** and alacritty is configured
    with `Osc52::OnlyCopy`, so a read is never answered or reported.
- A side scanner (`alacritty/sidechannel.rs`) picks up what alacritty ignores: OSC 7 (cwd),
  OSC 133 (prompt marks, with the cursor position at the mark), `CSI > 4 ; n m`
  (modifyOtherKeys) and `?1015` (urxvt mouse). It skips ground text with a byte search for ESC.
- Kitty keyboard requests are accepted (`kitty_keyboard = true`) and exposed in `TermModes`.
- Synchronized updates (`?2026`) are buffered by vte; `feed` flushes an expired one on entry,
  and `flush_expired_sync()` can be called from a timer if the remote goes quiet mid-update.
- **vte 0.15 bug workaround:** when a chunk ends inside a UTF-8 character and the next chunk
  completes it *and* continues with more text, vte's partial-UTF-8 path skips the bytes after
  the completed character (e.g. `"\xd7"` + `"\x9d \xd7\xa2"` loses the space). `feed` therefore
  holds back an incomplete trailing UTF-8 sequence (≤ 3 bytes) until the next call. Remove this
  once upstream fixes `Parser::advance_partial_utf8` (it returns `valid_bytes - old_bytes`
  instead of `c.len_utf8() - old_bytes`).

## `snapshot_vt` (SPEC §14.2)

Emits: RIS, palette reset, `?1049h` if the alternate screen is active, clear + home, OSC 4/10/11/12
overrides, every visible row (SGR transitions for colors incl. 256/RGB and underline color, bold,
dim, italic, underline styles `4:2…4:5`, inverse, hidden, strike; OSC 8 hyperlinks; wide chars;
combining chars; soft wraps preserved), then mode sets (DECCKM, DECKPAM, mouse 1000/1002/1003,
1005/1006/1015, 1004, 2004, 1007, IRM, LNM, DECTCEM, DECOM, kitty flags, modifyOtherKeys),
DECSCUSR, the cursor position (including the pending-wrap state), DECAWM and the current pen.

Not reproduced: scrollback, the primary screen while the alt screen is shown, the scroll region
(DECSTBM), tab stops, the saved cursor (DECSC), G0–G3 charset designations, the title stack.
The viewer starts with a full scroll region, which is what most full-screen apps re-establish
on their next redraw.

## Fallback emulator (`vt100` crate, SPEC §22.4) — swap cost

Nothing outside `alacritty/` names an alacritty type. A `vt100`-based implementation of
`Emulator` would need:

| Trait item | `vt100` support | Notes |
|---|---|---|
| `feed`, `resize`, `size` | `Parser::process`, `set_size` | direct |
| `modes` | `Screen::application_cursor`, `application_keypad`, `bracketed_paste`, `mouse_protocol_mode/encoding`, `alternate_screen`, `hide_cursor` | no focus reporting, kitty flags or modifyOtherKeys: reuse `sidechannel.rs` |
| `take_responses` | **none** — vt100 doesn't answer DA/DSR | must be generated by the wrapper (a small CSI scanner for `c`, `n`, `$p`, OSC 10/11) |
| `take_events` | `Callbacks` (title, bell, clipboard via `unhandled_osc`) | OSC 7/133 via the side scanner |
| `scrollback_len` | `set_scrollback` + probing | awkward but possible |
| `search` | none | implement over `Screen::rows` text |
| `snapshot_vt` | `Screen::state_formatted` + `contents_formatted` | close to what we emit |
| `cursor`, `grid_text` | `cursor_position`, `contents_between` | cursor shape isn't tracked |
| `hyperlink_at` | none | default method returns `None` |
| `render` | `Screen::cell` | M1-10 would need a second cell adapter |

Rough cost: a few days, mostly the query responder and search.

## Tests and fixtures

- `cargo test -p sverb-term` runs unit tests, `tests/emulator.rs` (T-02…T-18) and
  `tests/replay.rs` (T-01).
- Fixtures: `crates/sverb-term/tests/streams/*.bin`, recorded at 80×24 with
  `TERM=xterm-256color` under util-linux `script`. Re-record with
  `crates/sverb-term/tests/streams/record.sh [name…]`, then
  `INSTA_UPDATE=always cargo test -p sverb-term --test replay` and review the diffs in
  `tests/snapshots/`. Interactive programs (nvim, htop, tmux, less) are SIGKILLed while running
  so the final grid is the program's screen. `gen.sh` produces the SGR, UTF-8 and DECSTBM test
  patterns. Each replay also checks that feeding the stream in 1-, 7- and 64-byte chunks gives
  the same grid, and that `snapshot_vt` recreates it.
- Fuzzing: `cd crates/sverb-term/fuzz && cargo +nightly fuzz run emulator_feed` (needs
  `cargo-fuzz`). A proptest companion runs in CI.
- Throughput (T-19): `cargo bench -p sverb-term --bench emulator_throughput`. Measured on
  2026-10-07 on a heavily loaded 12-thread dev machine: ~99 MiB/s (≈ 104 MB/s) through
  `AlacrittyEmulator::feed`, vs 106.8 MB/s for bare `alacritty_terminal` on the same stream, so
  the wrapper costs ~3%. The ≥ 100 MB/s gate is enforced in M7-06.
